# TLG Academy: design (PROPOSED 2026-10-26, not built)

An online home for The Looking Glass Beauty School's courses at
`academy.tlg-beauty.co.uk`, hosted on AWS alongside the bot, with a student
login, Jess's approval gate, and placeholder YouTube videos until the
school hosts its own. Demo for the owners first; built so The CPD Group
could be given an assessor login later. Plan job 17 in `docs/plan.md`
tracks the steps; this file holds the design.

## Decisions taken (user, 2026-10-26)

- Subdomain, not a redirect page: `academy.tlg-beauty.co.uk` points at
  CloudFront; the WordPress site gets a nav link and a short landing page.
- Students self-register. Registering gives a login and nothing else; each
  course is unlocked only when Jess approves that student for it.
- Jess approves or rejects from her own login (an admin group).
- Every GitHub variable and secret for this stack is prefixed
  `TLG_ACADEMY_`; "accreditation pending" is one of those variables.
- Must work on desktop, Android and iPhone: one responsive web app, no
  native apps.
- No payments, no certificates generated, no own-hosted video in the demo.

## Architecture

Third Terraform stack, `terraform/academy/`, state key
`tlg-automation/prod/academy.tfstate`, resources `tlg-prod-academy-*`,
eu-west-2 except the CloudFront certificate (us-east-1).

| Piece | Choice | Why |
|---|---|---|
| Site | Static single-page app (Vite + React + TypeScript, Tailwind) in `academy/web/`, built in the pipeline, synced to a private S3 bucket behind CloudFront with an Origin Access Control | Cheapest, no servers, same pattern as any static site; responsive by construction |
| Domain | ACM certificate for `academy.tlg-beauty.co.uk` (us-east-1, DNS validation), CloudFront alias | Brand stays on the school's domain; cookies and links are first-party |
| Login | Cognito user pool, email sign-up with verification, hosted UI (prefix domain `tlg-academy.auth.eu-west-2.amazoncognito.com`, OAuth code flow with PKCE), groups `students` and `admins` | Self-registration and password reset without writing any of it; hosted UI pages are already mobile-friendly; a custom auth domain can come later |
| API | API Gateway HTTP API with a Cognito JWT authoriser, Python Lambdas in `src/academy/` | Same language and tooling as the bot |
| Data | One DynamoDB table `tlg-prod-academy`, PK/SK: `USER#<sub>` profile; `USER#<sub>/ENROL#<course>` with `status` pending, approved, rejected; `USER#<sub>/LESSON#<course>#<lesson>` completion | Minimal personal data: name, email, course, status, dates |
| Content | `academy/content/<course>/course.json` (title, exact accredited title, CPD fields, lessons) and `lesson-NN.md`; built into the app at deploy time | Content is data in the repo; swapping a YouTube id for an S3 video later changes one field |
| Private files | `tlg-prod-academy-files` bucket (manual PDF, handouts); API returns a presigned URL only for an approved enrolment | The manual is the course's intellectual property |
| Email | Cognito's default sender for verification and reset in the demo (50 a day) | Move to SES when real students arrive |

### The approval gate

1. Student registers (hosted UI), verifies email, lands on the academy.
2. First API call creates the profile and lists courses. Every course shows
   its description and a "Request access" button; no lesson is reachable.
3. "Request access" writes `ENROL#<course>` with status `pending`.
4. Jess, in the `admins` group, sees `/admin`: pending requests with name,
   email, course, date, and Approve / Reject buttons. A decision updates
   the status; the student sees it on next load. (Email on decision is a
   later step; the demo does not need it.)
5. Lessons and the manual download check `status == approved` server-side
   on every request, not just in the UI.

### CPD rules built into the templates

- Home and About pages: The CPD Group rosette and the Approved Provider
  logo, the latter linked to
  `https://thecpdregister.com/providers/cpd-group-providers--789824`.
- Course pages and course lists: never the rosette, never the provider
  logo. One "accredited activity badge" slot per course, filled only when
  `course.json` carries `cpd_accreditation_number`, `cpd_register_url` and
  the badge file The CPD Group issues, and only when the global switch is
  off.
- Global switch `TLG_ACADEMY_ACCREDITATION_PENDING`: `true` shows
  "CPD accreditation pending" on every course and hides every badge;
  `false` lets each course show its own badge if it has one. It is a
  GitHub variable so flipping it is a deploy, not a code change.
- Wording: "CPD course" and the exact accredited title; "accredited by The
  CPD Group" only when the badge is present. Delivery stays "classroom
  course with online pre-course study"; the academy does not claim to be
  the course.
- Certificates: not generated by the academy. A "Your certificate" panel
  explains it is issued after the taught day, the practical and the case
  studies, through The CPD Group's certificate tool.
- Accessibility: captions on every video (YouTube auto-captions at least),
  keyboard-navigable, contrast checked, text resizable, 44 px tap targets.
- Privacy: a privacy notice page naming TLG Beauty Limited as controller,
  what is stored and for how long; no analytics and no third-party cookies,
  so no cookie banner.

### Mobile

One layout from 360 px up: single column on phones, two columns from
900 px. Video embeds in a 16:9 box. Hosted UI handles the login screens.
Tested on Chrome for Android and Safari on iOS before anything is shown;
iOS Safari needs the `100dvh` viewport unit and no hover-only controls.
Optional later: a web app manifest so it can be added to the home screen.

## GitHub variables and secrets (environment `prod`)

| Name | Kind | Value | Used for |
|---|---|---|---|
| `TLG_ACADEMY_DOMAIN` | variable | `academy.tlg-beauty.co.uk` | ACM, CloudFront alias, Cognito callback URLs |
| `TLG_ACADEMY_ACCREDITATION_PENDING` | variable | `true` | The global wording and badge switch above |
| `TLG_ACADEMY_ADMIN_EMAILS` | variable | Jess's email (comma-separated for more) | Users placed in the `admins` group by a post-deploy step |
| `TLG_ACADEMY_CONTACT_EMAIL` | variable | academy contact address shown on the site | Footer, privacy notice |
| `TLG_ACADEMY_SUPPORT_PHONE` | variable | salon number | Footer |
| `TLG_ACADEMY_ENABLED` | variable | `true` | Lets the stack be torn down by variable if the demo is parked |

No secrets are needed for the demo; anything added later (an SES
identity ARN, a video-platform key, a payment key) follows the same
prefix: `TLG_ACADEMY_<NAME>`. Terraform reads them as `TF_VAR_academy_*`
in the deploy workflow, the web build reads the public ones as
`VITE_TLG_ACADEMY_*`.

## Krystal: the subdomain

DNS for tlg-beauty.co.uk is on Krystal's nameservers (ns1/ns2.krystal.uk),
so the records are added in Krystal's cPanel, Zone Editor. Two CNAME
records, both given by Terraform outputs after the first apply:

1. ACM validation: name like `_abc123.academy.tlg-beauty.co.uk`, value
   like `_xyz.acm-validations.aws.` (keep the trailing dot if cPanel
   asks for a fully qualified name). The certificate issues within minutes
   of the record resolving; Terraform waits for it.
2. The site: name `academy`, type CNAME, value the CloudFront domain
   `d1234abcd.cloudfront.net`, TTL 300 for the demo.

Steps in Krystal: log in to the client area, open the hosting package,
cPanel, Domains section, Zone Editor, "Manage" next to tlg-beauty.co.uk,
"Add Record", type CNAME. Do not add `academy` as a subdomain under
cPanel's "Domains" or "Subdomains" tool: that creates a folder on the
Krystal server and an A record that would fight the CNAME. Nothing about
the WordPress site, its A record, mail records or SPF changes.

On the WordPress side: a menu item "Academy" to
`https://academy.tlg-beauty.co.uk/`, and a short page
`/academy/` with one paragraph and the same link, so the word "academy"
on the website lands somewhere real while the subdomain propagates.

## Build steps (job 17)

1. `terraform/academy/`: S3 site bucket, OAC, CloudFront, ACM, Cognito
   pool, groups, app client, hosted UI domain, DynamoDB table, HTTP API,
   Lambdas, files bucket; outputs for the two Krystal records.
2. `src/academy/`: Lambda handlers (profile, courses, request access,
   admin list and decide, lesson complete, file link) with tests.
3. `academy/web/`: the app: home, about, courses, course page with lesson
   list and video, admin page, privacy notice; the pending switch; mobile
   layout.
4. `academy/content/builder-gel/`: the Builder Gel course as lessons from
   the manual's chapters, with placeholder YouTube ids, "accreditation
   pending".
5. `deploy.yml`: an `academy` job (terraform, npm build with the
   `VITE_TLG_ACADEMY_*` values, S3 sync, CloudFront invalidation, admin
   group bootstrap).
6. Krystal records, WordPress link and landing page; test on desktop,
   Android and iPhone; walk Jess through registering, requesting, and
   approving.

Order of work and estimates are on the plan job. Nothing starts until the
user says so.
